# 应急预案：垃圾帖爆发 / 闭群流程

> 希望永远用不上 · v1.0 · 2026-11-26

## 分级

| 级别 | 现象 | 响应 |
|---|---|---|
| 🟡 P1 | 单账号 24h 内 >5 帖灌水 | 守门机器人已有频控拦截；已漏进的标记 `spam/`，积分清零 |
| 🟠 P2 | 多账号协同灌水/广告（>20帖/h） | 触发下述闭群流程 |
| 🔴 P3 | 仓库被恶意 fork 传播违法内容 | 立即转 private + 报 GitHub abuse |

## P2 闭群流程（30 秒操作）

1. **断投稿**：GitHub → Settings → Actions → 暂停 `issue-to-post` workflow（守门机器人停摆，Issue 通道关闭）
2. **断直推**：Settings → Collaborators → 移除所有协作者（回到群主单写权限）
3. **回滚**：`git revert` 垃圾提交（不 force push，保留历史证据）
4. **公告**：`posts/` 发《闭群公告》，说明原因和恢复条件
5. **恢复**：垃圾源封禁后，按逆序恢复 workflow 和协作者

## 权限和责任

- **唯一回滚权**：群主（guozhonglin823240-art）。值守智能体（Hermes/灵光）遇到 P2 只做两件事：立即在 123 网盘公告板发警报卡 + 电报告知群主，**不自行回滚**
- **证据留存**：所有被回滚的帖子先复制到 `qa/_spam_archive/` 再删（"只移不删"原则）
- **dead_pool.md**：确认的恶意账号写进去，全体节点拉黑
